## 1. 第一轮的目标

第一轮不是直接迁移 GCN/HGCN 对照，而是先完成一个结构 gate：

> **确认 `mathlib4` 的受控子域里，是否存在 `longest_chain > 4` 的模块级 hierarchy 候选。**

## 3. 第一轮 Go / No-Go

### Go

如果出现至少一个候选模块满足：

1. `longest_chain > 4`
2. `relation_nodes >= 40`
3. `relation_edges >= 40`
4. `largest_relation_component >= 30`
5. `leaf_ratio <= 0.85`

那么下一步就做两件事：

1. 为该候选模块生成 relation-aware `parent_prediction` 配置
2. 直接迁移 multi-seed GCN/HGCN sweep

### Soft No-Go

如果 `Algebra + Order` 没有出现满足条件的候选，但：

1. `exact_extends_edge_count` 明显高于 `batteries`
2. 扫描结果中已有接近门槛的深层候选

那么不要立即放弃 `mathlib4`，而是切到第二轮备选：

```powershell
& 'C:\ProgramData\anaconda3\envs\DLEnv\python.exe' `
  'project_bootstrap/leandojo_graph_scaffold/src/filter_declaration_graph_by_modules.py' `
  --config 'project_bootstrap/next_traced_target_selection_package/configs/filter_mathlib_category_theory_hierarchy_probe_v1.json'
```

然后继续：

1. `extract_mathlib_category_theory_precise_coverage_v1.json`
2. `module_hierarchy_scan_mathlib_category_theory_precise_coverage_v1.json`

### Hard No-Go

如果连下面这些条件都不满足：

1. precise `extends` 数量没有明显提升
2. `skipped_exact_relation_rows_missing_nodes` 很高
3. 扫描后仍然只有 `longest_chain <= 4` 且组件极小

那么本轮不应继续迁移 baseline，应该先回到：

1. precise exporter / coverage 审计
2. 目标子域选择
3. 是否需要重新考虑 trace 粒度

## 4. 这一轮必须记录的字段

1. trace 文件数量
2. normalized declaration 数量
3. closed-world graph 规模
4. `Algebra + Order` 子图规模
5. precise `extends / instance_of` 数量
6. coverage-aware backfill 统计
7. 模块级扫描 top-k 候选
8. 是否出现 `longest_chain > 4`

## 5. 如果第一轮过 gate，第二轮做什么

如果第一轮过了 gate，下一步不是重新想方案，而是直接复用现有脚手架：

1. 为 top-1 / top-2 候选模块生成 `relation_gcn_*_parent_prediction_v1.json`
2. 生成对应 `relation_hgcn_*_parent_prediction_v1.json`
3. 生成对应 `relation_seed_sweep_*` 配置
4. 用 `run_dlenv_relation_seed_sweep.ps1` 跑五个 seed

到这里，才进入真正的“下一个 traced 目标上的模块级 GCN/HGCN 对照”。
