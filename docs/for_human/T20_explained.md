# T20 通俗解释

## 这个任务在做什么？

想象你面前有一堆已经做好的"体检报告"——这些报告描述了不同 Lean 数学库的"家谱图"（hierarchy graph）。每张图里，数学概念之间有"继承"关系（比如"环"继承"半环"的属性）。

问题是：我们想用**双曲空间**来表示这些家谱图（因为双曲空间天然适合表示树形结构），但之前发现效果不好。T20 的目标就是：**仔细看看这些体检报告，搞清楚到底是图本身的问题（图太浅了，像草坪而不是大树），还是模型的问题。**

具体来说，T20 做了三件事：
1. 把所有现有诊断报告放在一起看
2. 判断哪些图"太浅了不值得继续用双曲模型"（浅层 forest）
3. 判断哪些图"够深、够有层级，值得作为下一步实验的候选"

## 任务流程详解

### 输入
T20 读取了三份已有的诊断报告：
- `artifacts/diagnostics/real_graphs_v1/report.md` — 小型仓库（lean4-example、plausible、batteries）的图结构诊断
- `artifacts/diagnostics/hierarchy_focus_v1/report.md` — 聚焦层级结构的图诊断
- `artifacts/diagnostics/mathlib_order_focus_v1/report.md` — Mathlib 代数序相关模块的图诊断

### 产出
worker 新建了 `docs/diagnostics_summary.md`，包含：

1. **一张汇总表**：列出所有图的节点数、边数、最长链长度、多父节点数、叶子节点数、delta/maxdist（一种衡量"有多像双曲结构"的指标）
2. **浅层 vs 候选的分层判断**：明确哪些图太浅（只适合做参考对照）、哪些够深（可以作为下一步实验候选）
3. **候选优先级排序**：
   - 第1名：`mathlib_algebra_order_d3`（最深，最长链11，但碎片化严重）
   - 第2名：`mathlib_algebra_order_ring_d4`（深度接近，更紧凑实用）
   - 第3-4名：`ring_subring` 和 `field_subfield`（小型受控实验用）

### 同时更新的文档
- `04_task_board.md`：记录 T20 已完成 worker 执行，等待 review
- `07_handoff.md`：更新接手说明，反映 T20 的核心结论
- `08_risks_and_open_questions.md`：把 R04 风险的缓解策略从"先做诊断筛图"更新为"T20 已确认偏浅，后续优先转向更深候选"

### 对后续开发的意义
这个任务决定了下一步实验该选哪张图。之前的实验发现双曲模型效果不好，但可能不是模型的问题，而是图本身太浅（像星状森林而不是深层树）。T20 的结论指出：小型仓库的图确实太浅，但 Mathlib 代数序模块的图够深，值得作为下一步实验对象。后续的 T21（数据质量审计）和 T30+（训练对齐）都会参考这个优先级。

## 为什么 review 结果是 PASS_WITH_WARNINGS？

### 任务完成度
T20 的核心目标——复查诊断产物、形成候选图优先级表——已经达成。汇总表中的具体数字与原始诊断报告交叉验证后全部准确，优先级判断合理。

### 没有发现的问题
- 没有伪实现或 mock（这是文档任务，没有代码改动）
- 没有修改诊断产物或重跑脚本（遵守了 Forbidden scope）
- 没有把候选优先级写成最终实验结论（文档明确标注"provisional"和"not a final benchmark conclusion"）
- 所有改动都在 Allowed Files 范围内

### 为什么不是 PASS 而是 PASS_WITH_WARNINGS
有一个小瑕疵：汇总表中有几行用了 `n/a`（不适用/无数据），但原始诊断报告里其实有真实数字。比如 `plausible_*` 的关系层实际有 72 个节点、68 条边，但汇总表里写成 `n/a`。这不影响判断（plausible 确实极浅，longest chain 只有 1），也不影响优先级排序，但在数据准确性上留了一个小缺口。

另外，汇总表把"全图指标"和"关系层指标"混在同一张表里，没有标注每行数据来自哪个子表。虽然实际使用的都是关系层数据，但这种隐含的来源假设在后续引用时可能造成误解。

这两个问题都不阻塞任务完成，所以是 Warning 而非 Block。如果后续有方便的时机，可以补全这些 `n/a` 条目。
