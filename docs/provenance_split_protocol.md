# Provenance Split Protocol

> Updated: 2026-05-17
>
> Status: T40 worker draft, pending adversarial review.
>
> Purpose: Freeze the generation configs and output directory conventions for `explicit-only / synthesized-only / mixed` provenance-split graphs, so T41 (structural diagnostics) and T42 (grouped retrieval sweep) can consume them without re-defining the split semantics.

---

## 1. Provenance Semantics

The provenance split is defined on the `edge_type` field of `edges.csv`:

| `edge_type` | provenance origin | semantic meaning |
| --- | --- | --- |
| `extends` | `explicit` | Direct class/structure inheritance edges declared in Lean source |
| `instance_of` | `synthesized` | Type-class instance elaboration edges generated by the Lean compiler |
| `uses` | `unknown` | Declaration-level dependency edges from normalized trace |

This mapping is frozen as the `origin_map` in all T40 provenance split configs.

**Key constraint**: The current benchmark candidate graphs (`Field.Subfield`, `Order.Ring`) contain only `extends` and `instance_of` edges. They have no `uses` edges. Therefore the three provenance splits are:

1. **`explicit_only`**: edges where `edge_origin = explicit` (only `extends`)
2. **`synthesized_only`**: edges where `edge_origin = synthesized` (only `instance_of`)
3. **`hierarchy_mixed`**: edges where `edge_origin in {explicit, synthesized}` (`extends` + `instance_of`)

For these source graphs, `hierarchy_mixed` is identical to the full source graph.

## 2. Code Entry Point

Split execution uses the existing reviewed script:

```
project_bootstrap/leandojo_graph_scaffold/src/split_relations_by_provenance.py
```

Usage:

```bash
python project_bootstrap/leandojo_graph_scaffold/src/split_relations_by_provenance.py \
    --config <config_path>
```

The script reads `source_graphs[].graph_root`, annotates each edge with `edge_origin` via `origin_map`, filters edges by split definitions, writes filtered sub-graphs, and produces a `relation_split_summary.json`.

### 3.3 Config Schema

Each provenance split config must contain:

```json
{
  "_t40_frozen": true,
  "_description": "...",
  "source_graphs": [
    {"name": "<source_name>", "graph_root": "<path_to_source_graph>"}
  ],
  "output_root": "data/processed/declaration_graph",
  "origin_map": {
    "extends": "explicit",
    "instance_of": "synthesized"
  },
  "splits": {
    "explicit_only": ["explicit"],
    "synthesized_only": ["synthesized"],
    "hierarchy_mixed": ["explicit", "synthesized"]
  }
}
```

All T40-frozen configs use `_t40_frozen = true` to distinguish them from historical configs.

## 4. Output Directory Convention

### 4.1 Root

All provenance-split graphs are written under:

```
data/processed/declaration_graph/
```

### 4.2 Per-Split Directory Naming

Each split produces a subdirectory named:

```
{source_name}_{split_name}/
```

Specifically:

| Source | Split | Output Directory |
| --- | --- | --- |
| `mathlib_field_subfield_v1` | `explicit_only` | `data/processed/declaration_graph/mathlib_field_subfield_v1_explicit_only/` |
| `mathlib_field_subfield_v1` | `synthesized_only` | `data/processed/declaration_graph/mathlib_field_subfield_v1_synthesized_only/` |
| `mathlib_field_subfield_v1` | `hierarchy_mixed` | `data/processed/declaration_graph/mathlib_field_subfield_v1_hierarchy_mixed/` |
| `mathlib_order_ring_v1` | `explicit_only` | `data/processed/declaration_graph/mathlib_order_ring_v1_explicit_only/` |
| `mathlib_order_ring_v1` | `synthesized_only` | `data/processed/declaration_graph/mathlib_order_ring_v1_synthesized_only/` |
| `mathlib_order_ring_v1` | `hierarchy_mixed` | `data/processed/declaration_graph/mathlib_order_ring_v1_hierarchy_mixed/` |

### 4.3 Per-Split Output Files

Each output directory contains:

```
{output_dir}/
  declarations.csv   -- nodes referenced by the split edges
  edges.csv          -- split edges with edge_origin column
  stats.json         -- split statistics (num_nodes, num_edges, edge_type_counts, edge_origin_counts)
```

### 4.4 Summary File

A single summary file is written to:

```
{output_root}/relation_split_summary.json
```

This file contains the full provenance split statistics for all sources processed by the config.

## 6. T41 / T42 Usage Guide

### 6.1 T41: Structural Diagnostics on Provenance Splits

T41 should run structural diagnostics on each of the 6 provenance-split graph directories listed in Section 4.2. The diagnostics protocol is in `docs/diagnostics_protocol.md`.

Key comparisons:
- depth and longest chain across explicit-only vs synthesized-only vs hierarchy_mixed
- leaf ratio and component structure across provenance types
- hyperbolicity proxy comparison across splits

Config convention for T41 diagnostic configs:
- `graph_root` should point to the provenance-split output directories (Section 4.2)
- `relation_edge_types` should match the actual edge types present in the split (e.g., `["extends"]` for explicit_only, `["instance_of"]` for synthesized_only)

### 6.2 T42: Grouped Retrieval Sweep on Provenance Splits

T42 should run GCN and HGCN grouped retrieval sweeps on each provenance-split graph. For each provenance variant, the baseline config must adapt:

| Provenance Split | `target_relation_types` | `message_relation_types` | `hierarchy_relation_types` |
| --- | --- | --- | --- |
| explicit_only | `["extends"]` | `["extends"]` | `["extends"]` |
| synthesized_only | `["instance_of"]` | `["instance_of"]` | `["instance_of"]` |
| hierarchy_mixed | `["extends", "instance_of"]` | `["extends", "instance_of"]` | `["extends", "instance_of"]` |

Config convention for T42 baseline configs:
- `graph_root` should point to the provenance-split output directories (Section 4.2)
- `run_id` should follow: `grouped_{model}_provenance_{source}_{split}_t42`
- `artifacts_root` should follow: `artifacts/baselines/relation_seed_sweeps/grouped_{model}_provenance_{source}_{split}_t42/`
- All other config fields should match the T32/T33 reviewed grouped training pattern

### 6.3 Critical Constraint for T41/T42

The `hierarchy_mixed` split is identical to the full source graph for both candidates (since neither source has `uses` edges). T41/T42 should verify this identity by comparing node/edge counts before drawing conclusions.

## 7. Provenance Split Integrity Rules

1. The `origin_map` must not be modified after T40 freeze. Changing provenance semantics to pursue favorable model results is forbidden.
2. The split names (`explicit_only`, `synthesized_only`, `hierarchy_mixed`) must not be renamed or merged.
3. The output directory naming convention must be preserved across T41/T42.
4. Historical configs (e.g., `relation_split_batteries_v1.json`) must not be overwritten.
5. If a new source graph is added for provenance split, a new config file must be created; existing configs must not be modified.
6. The `_t40_frozen` marker in config files indicates the config has been reviewed and should not be changed without a new task package.
