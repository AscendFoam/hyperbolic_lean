# 双曲优势假设的诊断分析与替代方向

> 写作日期：2026-04-30
>
> 本文基于项目中已完成的真实实验数据（lean4-example、plausible 两个仓库，覆盖从第一版双曲 baseline 到 HGCN v3 rescaling、edge ablation、parent prediction 等多轮对照），对"为什么直觉上双曲几何应该有优势但实验中没有观察到"这一问题做系统归因分析，并据此提出更可行的研究方向建议。

---

## 1. 直觉链条回顾

项目启动时，从多份调研报告和前期讨论中形成了一条看起来非常合理的推理链：

```
数学概念天然具有层级结构
        ↓  例：Semigroup → Monoid → Group → CommGroup
层级结构在几何上表现为树或类树 DAG
        ↓
双曲空间具有指数级体积增长，天然适合嵌入树形结构
        ↓  例：Poincaré ball 的边界区域可以容纳指数多的叶节点
因此，用双曲嵌入来表示形式化数学图谱应该优于欧氏嵌入
        ↓  特别是在低维场景下，双曲应该有明显的压缩优势
```

这条推理链的**每一步单独看都成立**：

- 数学 typeclass 确实有层级：Lean 4 中 `CommGroup extends Group extends Monoid extends Semigroup`。
- 树形结构确实在双曲空间中有最优嵌入：Sarkar (2011) 证明了任何树可以在 2 维双曲空间中以 O(1) 失真嵌入。
- 低维压缩确实是双曲的强项：Nickel & Kiela (2017) 展示了 Poincaré embedding 在 5-10 维就能达到 word2Vec 几百维的效果。

然而，从第一版双曲 baseline（test AP = 0.4196）到 HGCN v3 rescaling（test AP = 0.6642），**在所有实验条件下，双曲模型从未稳定超过欧氏 GCN**。这说明推理链的某个环节在实际数据上断裂了。下面逐层拆解。

---

## 2. 断裂诊断：为什么直觉没有兑现

### 2.1 断裂一：图中的真正层级边密度极低

这是最根本的原因。

项目直觉中的"层级"指的是 typeclass 继承链（`extends`），以及 instance 与其目标 typeclass 之间的关系（`instance_of`）。但在实际抽取的 declaration graph 中，这两类边占的比例极小：

| 图 | 总边数 | `uses` | `instance_of` | `extends` | `extends` 占比 |
|---|---|---|---|---|---|
| `full_precise_v1`（全图） | 86,324 | 85,346 | 959 | **19** | **0.02%** |
| `typeclass_precise_v2`（子图） | 3,733 | 2,755 | 959 | **19** | **0.5%** |

**19 条 `extends` 边。** 这是整个图中真正意义上的"父子继承"关系——也就是双曲几何最应该发挥优势的结构。它占全图边数的 0.02%。

双曲空间对树形结构的最优嵌入定理要求被嵌入的对象**确实是一棵树（或高度类树的 DAG）**。当 99.98% 的边不是层级边时，双曲的归纳偏置实际上是一个**错误的先验**：它在用"指数体积增长"的假设去拟合一张几乎没有层级结构的图。

更具体地说，双曲空间的指数体积增长意味着：靠近原点的区域体积小（适合放根节点），靠近边界的区域体积大（适合放叶节点）。但如果图中根本没有足够深的层级链，这个几何特性就无从发挥——所有节点都挤在原点附近，双曲空间的优势维度（径向方向）没有被利用。

### 2.2 断裂二：正式数学依赖图更像小世界网络，而非树

直觉中的层级图景是纵向扩展的树：

```
MathObj
├── Algebraic
│   ├── Group
│   │   ├── CommGroup
│   │   └── FinGroup
│   └── Ring
├── Topological
│   ├── Compact
│   └── Hausdorff
```

但实际 Lean/Mathlib 中的依赖结构更像是横向交叉的网络：

```
theorem X : uses [Group.Basic, Topology.Basics, Order.Filter, Logic.Basic]
theorem Y : uses [X, Group.CommGroup, Analysis.Normed.Basic]
instance Z : CommGroup → TopologicalGroup   -- 跨域桥接
def W : uses [Z, X, Y, CategoryTheory.Functor]  -- 多源汇聚
```

这种结构的特征是：

1. **路径长度短**：从任意声明出发，通常 2-3 步就能到达另一个看似不相关的领域（小世界性质）。
2. **聚类系数高**：同一模块内的声明彼此密集引用，形成紧密的团簇。
3. **度分布偏重尾**：少数基础声明（如 `Eq.refl`、`And.intro`）被大量下游使用，形成 hub。

这正是小世界网络（small-world network）的特征。而小世界网络的几何性质是：**Gromov 双曲性 δ 相对于直径来说偏大**，意味着它在度量几何上更接近欧氏空间，而非双曲空间。

> **关键缺失**：方案 Section 6.1 (T0) 明确要求"在投入双曲模型之前，先做图结构诊断"，包括 Gromov hyperbolicity、tree-likeness、ancestor/descendant 分布等。但实际执行中跳过了这一步直接训练模型。如果先算了 Gromov hyperbolicity，很可能发现 δ/diameter 远大于树状结构的典型值，从而在建模之前就预见到双曲优势不会出现。

### 2.3 断裂三：link prediction 任务对层级结构不敏感

项目的默认评测任务是二值 link prediction：给定两个节点，预测它们之间是否存在边。这个任务有几个根本性局限：

**a) 不区分边类型。** `extends`（继承）和 `uses`（使用）被当作同一种二元关系处理。但双曲几何的优势应该只体现在层级边上——如果一个任务把 99% 的非层级边和 1% 的层级边混在一起评价，层级边上的微小优势会被稀释。

**b) 不测量层级排序质量。** link prediction 只关心"有没有边"，而不关心"谁是最近的祖先"、"层级距离是多少"。但双曲空间的真正优势在于径向距离可以编码层级深度——如果一个任务不利用这个信息，双曲的空间结构就是多余的。

**c) negative sampling 策略的影响。** 当前默认的 `same_module harder negatives` 会使负例集中在与正例同一模块的节点对上。但同一模块内的节点通常处于相似的层级深度，这恰好是双曲空间最难区分的区域（因为同深度的节点在双曲空间中彼此接近）。

16.22 节中补做的 `parent_prediction` 和 `ancestor_ranking` 试图解决上述问题，方向是正确的。但结果仍然显示 GCN 在 ranking 指标上大幅领先（`MRR = 0.1565 vs 0.0450`，`Hits@10 = 0.3125 vs 0.0729`）。这进一步说明：即使任务被设计成层级敏感的，当前 HGCN 模型也没有学到有效的层级排序信号。而这很可能与下一层断裂（模型设计）有关。

### 2.4 断裂四：HGCN 模型并没有真正利用双曲几何的层级归纳偏置

16.21 节的 edge ablation 实验是整个项目中**诊断价值最高**的一组实验，但它的结果与双曲直觉**完全相反**：

| 子图 | GCN test AP | HGCN v3 test AP | HGCN 相对 GCN |
|---|---|---|---|
| `uses-only`（非层级） | 0.7629 | **0.5616**（HGCN 最佳） | -26.4% |
| `instance-only`（部分层级） | 0.7065 | 0.5009 | -29.1% |
| `hierarchy-only`（最层级） | 0.7064 | **0.4628**（HGCN 最差） | -34.5% |
| `full precise v2` | 0.8013 | 0.6642 | -17.1% |

如果 HGCN 真正利用了双曲几何对层级结构的编码能力，那么移除非层级边（`uses`）后，HGCN 应该表现**更好**——因为剩下的就是纯层级结构，正是双曲空间的用武之地。但实际结果恰恰相反：HGCN 在最纯的层级图上表现最差，在非层级图上反而最好。

这说明当前 HGCN 的实际工作模式是：

1. 切空间聚合本质上还是邻域平均——和 GCN 做的事情类似。
2. 投影到 Poincaré ball 后，距离度量的变化并没有被解码器有效利用。
3. 模型学到的仍然是局部邻域结构信号，而不是全局层级拓扑。

换言之，**当前的 HGCN 只是一个"在双曲空间里做 GCN"的模型，而不是一个"利用双曲几何归纳偏置来编码层级结构"的模型**。这两者之间有本质区别：前者只是换了度量空间但保留了相同的算法逻辑，后者需要显式地设计能够捕获层级距离的聚合和解码机制。

### 2.5 断裂五：双曲模型的数值工程困难干扰了核心判断

从 16.5 节到 16.20 节，实验精力的大量消耗可以用一条时间线概括：

```
v1：raw test F1 = 0.0 → 发现 decoder 距离惩罚主导 logit → 温度缩放修复
v2：raw test F1 仍然很低 → 发现 batch 级 z-score + tanh 有界化可缓解
v3：rescaling 后 raw F1 恢复到 0.5944 → 但温度参数仍然异常（T = 1.68）
precise v2 上 → 再次出现 raw F1 = 0.0 → 再次做 rescaling → 修复后 AP 从 0.5992 升到 0.6696
```

这些问题的根源在于双曲模型的工程复杂性：

1. **Poincaré ball 边界处的梯度趋向无穷**，需要精心设计的投影和裁剪。
2. **`acosh` 在零附近数值不稳定**，需要 `log1p` 等近似实现。
3. **Möbius 加法不满足交换律和结合律**，使得标准的 batch normalization 和残差连接不能直接套用。
4. **距离项的量纲与 MLP 分支不匹配**，导致 logit 分布严重偏移。

这些问题使得"双曲模型是否在几何上更优"这一核心科学问题被"双曲模型能否稳定训练"这一工程问题所掩盖。在 decoder 的距离项尺度修复之前，HGCN 的低性能可能纯粹是工程问题而非几何问题；但在修复之后，HGCN 仍然没有超过 GCN，则说明**工程问题只是部分原因，更根本的原因还是在于 2.1-2.4 所述的结构性错配**。

### 2.6 五层断裂的总结

| 层次 | 直觉假设 | 实际情况 |
|---|---|---|
| 图结构 | 层级边是图的主要成分 | 层级边（`extends`）仅占 0.02%，`uses` 占 98.7% |
| 图几何 | 图是树状/类树的 | 图更像小世界网络（短路径 + 高聚类） |
| 任务设计 | link prediction 能暴露几何优势 | link prediction 不区分边类型，对层级结构不敏感 |
| 模型设计 | HGCN 利用双曲归纳偏置 | HGCN 本质上还是邻域聚合，没有真正编码层级距离 |
| 工程实现 | 双曲模型可以稳定训练 | 数值稳定性问题消耗了大量实验精力 |

这五层断裂不是独立的，而是**层层叠加**的：图的层级信号本就微弱（2.1），任务又不善于捕获这种微弱信号（2.3），模型也没有利用仅有的信号（2.4），工程问题又进一步掩盖了信号（2.5）。最终的结果就是：即使双曲几何在理论上确实更适合层级结构，在当前的图-任务-模型组合下，这个理论优势完全没有释放的通道。

## 3. 更深层的原因：正式数学的"层级"不同于直觉中的"层级"

### 3.1 概念层级 vs 依赖层级

Gemini 和 Doubao 的调研报告中引用的层级例子主要是**概念层级**（concept hierarchy）：

```
Semigroup → Monoid → Group → AbelianGroup
```

这条链确实是深层的树状结构。但 declaration graph 建模的不是概念层级，而是**依赖层级**（dependency hierarchy）：

```
theorem foo : uses [bar, baz, quux]
```

这两者有本质区别：

- **概念层级**是静态的、全局的：`Group extends Monoid` 这个事实在 Mathlib 的整个生命周期中不变。
- **依赖层级**是动态的、局部的：一个 theorem `uses` 哪些 declaration 取决于具体的证明策略，同一个数学命题可以有多种不同的证明路径。

概念层级确实像一棵树（或浅森林），但依赖层级更像一个**多源多汇的 DAG**，其中大量边是横向的跨域引用，而非纵向的继承。

### 3.2 为什么 lean4-example 中的 extends 这么少

lean4-example 是一个教学级小仓库，它主要包含基础定义和练习题，而不是 Mathlib 级别的深层抽象层级。在 lean4-example 中：

- 大多数声明是 `def`、`theorem`、`lemma`
- 只有极少数 `class` 声明（2 个）
- `structure` 声明虽然较多（1145 个），但大多数不是 typeclass，而是普通数据结构
- 真正有 `extends` 关系的类声明只有 19 个

这意味着当前实验的**数据基础本身就不足以检验双曲层级假设**。在一个只有 19 条继承边的图上，任何关于"层级结构是否适合双曲建模"的结论都缺乏统计功效。

### 3.3 plausible 仓库的验证

plausible 仓库的实验进一步印证了上述分析。plausible 是一个真实的、typeclass-heavy 的小仓库（68 条 `instance_of` 边），但几乎没有内部 `extends` 边。在这个仓库上：

- GCN: `test AP = 0.7285`，校准后 `F1 = 0.6316`
- HGCN: `test AP = 0.6047`，校准后 `F1 = 0.5455`

GCN 仍然明显优于 HGCN。这进一步说明：**即使在一个真实的、typeclass 密集的仓库上，只要缺乏足够深的继承层级（`extends`），双曲方法就无法建立优势。**

## 4. 替代研究方向建议

基于以上诊断，以下是五个可能更可行的研究方向，按风险从低到高排列。

### 4.1 方向 A：形式化数学图谱作为数据集/基准贡献（风险最低）

**核心思路**：放弃"双曲 vs 欧氏"作为核心 claim，转而把数据工程和评测框架作为主要贡献。

**已有基础**：

- 完整的 `LeanDojo trace → 归一化 → closed-world graph → precise hierarchy join` 管线
- 两个真实仓库（lean4-example、plausible）上的端到端验证
- 统一的评测协议：`same_module harder negatives + temperature scaling + validation-max-F1 threshold`
- 完整的欧氏 baseline 组（Node2Vec、GCN、多维扫描）
- edge ablation 和子图对照

**论文故事线**：

> FormalMathGraph: A Reproducible Formal Mathematical Dependency Graph Benchmark

核心贡献：

1. 首个从 LeanDojo trace 到精确层级图的公开可复现管线
2. closed-world / open-world 边界定义的讨论
3. 三值标签体系（positive / negative / unknown）
4. 模块切分 vs 边切分 vs 随机切分的对比
5. 一组完整的欧氏 baseline + probing 结果
6. edge-type ablation 揭示的图结构特征

**优势**：结果已经有了，不需要再赌双曲是否占优；数据集/基准论文有稳定的发表渠道（NeurIPS Datasets, TMLR）。

**风险**：novelty 可能被认为不足；需要在更大规模 Mathlib 子集上复现才有说服力。

### 4.2 方向 B：图结构诊断作为独立研究（风险低，是所有后续方向的必要前提）

**核心思路**：把"正式数学图谱到底长什么样"作为研究问题本身，而不是预设它适合某种几何。

**具体内容**：

1. **Gromov hyperbolicity 计算**：对 Mathlib 的不同子域（Algebra、Topology、Analysis、CategoryTheory）分别计算近似 δ，判断哪些子域更 tree-like。
2. **Tree-likeness 量化**：使用 tree-depth、treewidth 等图论指标。
3. **度分布分析**：区分 `uses` 边和 `extends` 边的度分布差异。
4. **社区结构分析**：使用 Louvain/Leiden 等算法发现 Mathlib 的"自然子域"。
5. **层级深度统计**：在 typeclass 继承子图上，计算最大深度、平均深度、深度分布。
6. **跨域引用模式**：分析不同子域之间的 `uses` 边密度矩阵。

**可能的发现**：

> "形式化数学依赖图在不同子域表现出截然不同的几何特征：代数子域的 typeclass 继承链更深层级化（潜在适合双曲），而分析和拓扑子域的依赖模式更网状化（更适合欧氏）。"

这个结论本身就很有价值——它为后续研究者选择几何模型提供了**数据驱动的指导**，而不是基于先验直觉。

**优势**：纯粹分析性工作，不需要训练模型；对社区有参考价值；可以作为方向 A 的增强版。

**风险**：需要跑通更大规模的 Mathlib trace，工程量不小。

### 4.3 方向 C：性质 Probing 作为核心实验（风险中等）

**核心思路**：不改模型架构，改研究问题。从"双曲是否更好"转向"图表示到底编码了什么数学结构"。

**具体内容**：

1. 在已训练好的 GCN/HGCN 表征上做线性 probe 和 MLP probe。
2. 预测的标签包括：
   - **结构性标签**：`def / theorem / lemma / class / instance`（稳定、无歧义）
   - **子域标签**：所属 Mathlib 模块族（`Algebra / Topology / Analysis / ...`）
   - **typeclass 属性**：`CommGroup / Finite / CompactSpace / ...`（使用 Lean 元编程精确抽取）
   - **复杂度标签**：AST 大小、证明长度、依赖深度

3. 关键实验设计：
   - **维度敏感性**：在 2、4、8、16、32、64 维表征上分别做 probe，比较 probe 性能随维度的变化曲线。
   - **线性 vs 非线性**：如果线性 probe 就有效，说明表示空间更有解释力。
   - **跨切分泛化**：在模块切分下做 probe，测试泛化到训练时未见过的子域。

**论文故事线**：

> What Do Graph Neural Networks Learn About Formal Mathematics? A Probing Study

核心 claim 不需要"双曲更好"——只需要证明"图表示确实编码了有意义的数学性质"。如果发现双曲表示在某些 probing 任务上表现不同（不是更好或更差，而是**不同的**），这本身就是一个有趣的发现。

**优势**：实验设计成熟（probing 是 NLP 中标准的研究范式）；对表示学习的理解有贡献；不需要双曲模型占优。

**风险**：需要更多标签数据；probing 结果可能不够 surprising。

### 4.4 方向 D：面向定理证明的检索与推荐（风险中等，应用价值最高）

**核心思路**：把研究重心从"几何表示"移到"实用检索"，关注图表示是否真的能帮助定理证明。

**具体内容**：

1. **theorem retrieval**：给定一个定理陈述或 goal 描述，从 Mathlib 中检索最相关的声明。
2. **proof-state retrieval**：给定当前 proof state，检索历史上相似的 state 和成功的 tactic。
3. **tactic ranking**：给定 proof state 和候选 tactics，排序哪个更可能成功。

基线对照：

- BM25 / lexical retrieval
- dense text retrieval（LeanDojo 已有 baseline）
- graph embedding retrieval（使用已有的 GCN 表征）
- graph + text hybrid retrieval

**评测指标**：

- `Recall@k`、`MRR`、`nDCG`
- `compile-success@k`（最强信号：检索到的 tactic 是否真的能让 Lean 编译通过）

**论文故事线**：

> Graph-Enhanced Retrieval for Formal Theorem Proving

核心 claim：图结构提供了文本检索无法捕获的互补信息，即使图嵌入本身不是最优的，它对检索的增量贡献是显著的。

**优势**：与 ITP 社区最接轨；应用价值明确；可以利用已有的 GCN 表征。

**风险**：需要 `proof-state` 级别的数据（当前主要在声明级别）；与 Graph2Tac、ReProver 等已有工作竞争。

### 4.5 方向 E：基于类型论的表示学习（风险最高，创新性最强）

**核心思路**：跳出"把声明当节点、把依赖当边"的通用图嵌入范式，直接在 Lean 的类型论结构上做表示学习。

**动机**：

当前所有实验（GCN、HGCN、Node2Vec）本质上都是：把 Lean 声明当成无类型图节点，把所有依赖关系当成无类型边，然后用通用图算法做嵌入。这丢弃了 Lean 4 依赖类型论中丰富的结构信息：

- **dependent type 的参数关系**：`List α` 中的 `α` 如何约束后续使用。
- **universe level 的层级**：`Type u` 中的 `u` 提供了另一层抽象层级。
- **typeclass 综合的搜索路径**：instance resolution 的搜索树本身就是有向无环图。
- **tactic script 的操作语义**：每个 tactic 对 goal 的变换可以用状态转移图描述。

**可能的实现路径**：

1. 在 Lean expression（而非 declaration）级别构建图，节点是子表达式，边是语法关系。
2. 使用类型感知的 GNN：节点的初始表征来自类型信息，消息传递沿着类型依赖关系进行。
3. 或者更激进地：不做图嵌入，而是做 expression tree 的序列建模（类似 AlphaCode 对程序的处理），用 Transformer 直接在 Lean AST 上训练。

**优势**：真正的类型论原生方法在学术上是新的；与 program representation learning 领域有交叉。

**风险**：工程量极大；可能需要从头设计模型和评测体系；不保证结果优于现有方法。

## 5. 如果仍然想继续推进双曲方向

如果出于学术兴趣或导师要求仍然希望继续探索双曲方法，以下条件必须同时满足，否则实验结果不会比当前更有说服力：

### 5.1 必须先完成图结构诊断

在训练任何双曲模型之前，先回答以下问题：

1. 目标子图的 **Gromov hyperbolicity δ** 是多少？δ 相对于直径的比例是多少？
2. 目标子图的 **treewidth** 是多少？是否足够小以至于近似树？
3. 目标子图中 `extends` 边构成的子图的**最大深度**是多少？
4. 目标子图的 **度分布** 是否符合幂律（scale-free）？

只有当这些指标明确表明图的某个子域确实高度 tree-like 时，双曲建模才有合理的先验支撑。

### 5.2 必须在更大规模的 Mathlib 子集上实验

lean4-example 只有 19 条 `extends` 边，plausible 有 0 条。这两个仓库都不足以检验双曲层级假设。需要找一个 `extends` 边数量在 **1000+** 的 Mathlib 子集（例如 `Mathlib.Algebra` 全部），才能有足够的统计功效。

### 5.3 必须设计层级敏感的任务

标准 link prediction 不够。建议采用：

1. **typed link prediction**：只预测 `extends` 边，而非所有边。
2. **ancestor ranking**：给定一个节点，对其所有祖先按层级距离排序。
3. **lowest common ancestor prediction**：给定两个节点，预测它们的最近公共祖先。
4. **depth prediction**：从嵌入预测节点在层级中的深度。

这些任务直接测试双曲空间的核心能力——径向编码层级深度。

### 5.4 必须设计真正利用双曲几何的模型

当前的 HGCN 本质上是"在双曲空间做 GCN"。需要的是"利用双曲几何归纳偏置的模型"，例如：

1. **显式径向编码**：让模型的目标函数显式包含"到原点的距离应编码层级深度"。
2. **角度编码语义**：让同一层级深度的不同概念在角度方向上分开。
3. **层级感知的解码器**：解码器不应只看双曲距离，还应看径向差和角度差的不同组合。
4. **可学习曲率**：不同子域的最优曲率可能不同，应该让模型自适应。

## 6. 总结

### 6.1 核心结论

本项目的主线假设——"形式化数学图谱的层级结构使双曲表示优于欧氏表示"——在当前实验条件下没有得到支持。原因不是双曲几何本身有问题，而是：

1. **图结构的层级密度远低于预期**（`extends` 边仅占 0.02%）。
2. **图的整体几何特征更接近小世界网络而非树**。
3. **评测任务不区分层级和非层级关系**。
4. **当前双曲模型没有真正利用层级归纳偏置**。
5. **数值工程困难干扰了对核心问题的判断**。

### 6.2 最建议的方向

| 优先级 | 方向 | 核心贡献 | 风险 | 已有基础 |
|---|---|---|---|---|
| 1 | **B：图结构诊断** | 首个对 Mathlib 依赖图几何特征的系统分析 | 低 | 需扩展到更大 Mathlib 子集 |
| 2 | **A：数据集/基准** | 首个可复现的 Lean 依赖图数据集 | 低 | 管线已通，结果已有 |
| 3 | **C：性质 Probing** | 揭示图表示编码了哪些数学性质 | 中 | GCN 表征已有，标签需补充 |
| 4 | **D：检索与推荐** | 图增强的定理检索 | 中 | 需补 proof-state 级数据 |
| 5 | **E：类型论原生** | 类型论感知的表示学习 | 高 | 需从头设计 |

**最稳妥的路径**：先完成方向 B（图结构诊断），根据诊断结果决定是继续推进双曲（如果某些子域确实高度 tree-like）还是转向方向 A/C（如果全面 tree-like 证据不足）。方向 B 的结果本身就是一篇有价值的分析论文，同时为所有后续方向提供数据基础。

### 6.3 一句话概括

> **双曲几何对形式化数学图谱是否有优势，目前不是"被证伪了"，而是"没有被恰当地测试过"——当前的图、任务和模型三者都没有真正对准双曲几何的核心能力（编码深层树形层级）。要得到可信的结论，必须先在足够大、足够纯的层级子图上，用层级敏感的任务，配合真正利用双曲归纳偏置的模型来做对照。在此之前，更合理的论文定位是"形式化数学图谱的数据工程与几何诊断"，而不是"双曲优于欧氏"。**
