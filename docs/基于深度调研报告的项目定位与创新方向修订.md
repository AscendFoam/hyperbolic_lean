# 基于深度调研报告的项目定位与创新方向修订

> 更新时间：2026-05-01
>
> 目的：在 [深度调研报告.md](d:/Codes/Math/hyperbolic_lean/docs/深度调研报告.md) 的基础上，重新界定本项目的研究边界、已被覆盖的已有工作、当前独特点，以及下一步更具创新性的推进路线。

---

## 1. 核心判断

结合公开调研与当前已经完成的工程和实验，可以把本项目的定位压缩成一句话：

> 本项目的真正创新点，不应再表述为“在 Lean/Mathlib 图上训练一个更强的双曲模型”，而应收敛为“构建真实 traced formal-math hierarchy 图的可复现实验管线、标准化任务协议与结构诊断框架，并系统分析双曲归纳偏置在何种数据条件下可能有效”。

这一判断有两个直接含义。

第一，项目**没有被现有工作完整做掉**。虽然 Lean/Mathlib 生态已经存在较成熟的 trace/export/graph-analysis 工具链，但公开文献与开源项目中，尚未看到一条与本项目完全重合的路线：即围绕真实 traced Lean hierarchy 图，系统完成 precise hierarchy 抽取、coverage-aware 修复、relation-aware 子图建模、grouped retrieval 协议以及 GCN/HGCN 的公平对照诊断。

第二，项目中也确实有一部分工作**已经有明显前人覆盖**。因此，后续写作和实验不应再把“能导出 Lean 图”或“能做基础图统计”本身当成主要贡献，而应把重点放在“协议、诊断、边界条件与任务化 benchmark”上。

---

## 2. 哪些部分已经被做过了

根据 [深度调研报告.md](d:/Codes/Math/hyperbolic_lean/docs/深度调研报告.md) 的整理，以下几类工作已经有较强先行基础。

### 2.1 Lean/Mathlib 图数据的导出与追踪

这部分已经形成相当完整的生态：

- `importGraph` 已经覆盖模块导入图的导出与可视化。
- `lean4export` 已经覆盖声明环境及其传递依赖的 NDJSON 导出。
- `LeanDojo / LeanDojo-v2 / lean-training-data / jixia / Pantograph` 已经覆盖 proof state、premise、AST、symbol reference、elaboration trace 等 traced 数据层。
- `doc-gen4`、`mathlib4_docs` 等工具已提供面向声明和文档层的组织方式。

因此，如果项目主张只是“我们也能把 Lean/Mathlib 图导出来”，那么新意显然不够。

### 2.2 Lean/Mathlib 图的基础网络分析

这部分也已有明确前人工作：

- 《The Network Structure of Mathlib》已经区分 declaration dependency、statement dependency、pure proof dependency、typeclass/coercion/structure graph 等层。
- `mathlib-network` 已经把多层图标准化成 CSV 形式并开放数据资产。
- `ProofGraph` 已经把 Lean 依赖图作为网络科学对象进行谱分析和原型系统探索。

因此，如果项目只停留在“对 Mathlib 图做规模统计、基本结构描述或静态分析”，也很容易落到已有工作的阴影下。

### 2.3 一般性的双曲图学习方法

双曲嵌入与双曲图学习本身当然不是空白：

- `Poincare Embeddings`
- `HGCN`
- `RotH / RefH / AttH`
- `HypHKGE`
- 以及更近期的 hierarchy-aware hyperbolic KG / GNN 方法

这些方法已经证明“双曲几何在层级结构和低维表示上可能有优势”，但它们并没有直接解决 Lean/Mathlib traced hierarchy 图的问题。因此，项目不能把“用了双曲模型”本身当成创新点。

---

## 3. 当前项目的独特点在哪里

与上述已有工作相比，本项目已经形成的独特点主要在于“把几条原本分散的线真正接起来了”。

### 3.1 从 trace 到 hierarchy 子图，再到统一协议的闭环

当前项目不只是做导出，而是已经跑通了从真实 Lean 仓库 trace 到后续实验的完整闭环：

- traced repo 抽取
- normalized trace 适配
- declaration graph 构建
- precise `extends / instance_of` 抽取
- coverage-aware relation backfill
- relation-aware 子图构建
- baseline 与诊断对照

这使得项目天然具备“可复现实验管线”的雏形，而不仅是一次性的 exploratory script。

### 3.2 对 hierarchy 图做了比公开工具更严格的任务化整理

本项目目前最明显的独特点之一，是没有停在“图构建完成”这一步，而是继续做了面向学习任务的协议设计：

- 把 `decl_name / declaration_id` 统一升级到全限定名
- 把 precise hierarchy 子图与旧 ID 体系解耦后重跑
- 区分 `uses / extends / instance_of`
- 做 relation-aware 而不是单一边类型压平

这一点很重要，因为公开工具链大多提供原始数据或导出接口，而不是一套可直接比较模型的规范任务协议。

### 3.3 对 ancestor 任务的评测口径做了实质修正

这一点是当前项目最值得保留的核心成果之一。

在 [阶段总结（2026-05-01，grouped ancestor retrieval）.md](d:/Codes/Math/hyperbolic_lean/docs/阶段总结（2026-05-01，grouped%20ancestor%20retrieval）.md) 中，我们已经证明：

- 旧的单正例 `ancestor_ranking` 与真实任务结构明显错配
- 更合理的协议应当是 grouped multi-positive retrieval
- 评测指标应改为 grouped `Recall@k / MAP / nDCG / grouped-MRR`
- 并补充按 hop 分桶的分析

这一点不是简单的“多加几个指标”，而是在任务定义层面对已有基线进行了纠偏。

### 3.4 对“双曲为什么没赢”给出了结构性解释，而不只是经验负结果

在 [双曲优势假设的诊断分析与替代方向.md](d:/Codes/Math/hyperbolic_lean/docs/双曲优势假设的诊断分析与替代方向.md) 中，项目已经不再停留在“实验结果里 HGCN 没赢”。

相反，我们已经把结论推进到了更强的一层：

- 当前 relation layer 很干净，但主要是浅层、碎片化、叶子占优的 forest
- 很多图虽然 tree-like，但并不是深层 hierarchy tree，而更像 instance-to-class 的 star forest
- 因此，双曲归纳偏置没有被自然释放，并不等同于“模型训练失败”

这使项目从“模型对照”提升成了“结构诊断 + 条件性结论”。

---

## 4. 当前最合理的论文主张

基于上面的分析，项目后续最合理的主张不应是：

> 我们提出了一个新的双曲模型，并在 Lean/Mathlib hierarchy 图上优于欧氏基线。

而应写成：

> 我们构建了一套面向真实 traced Lean/Mathlib hierarchy 图的可复现实验管线，提出了更符合 formal-math hierarchy 任务结构的标准化协议，并通过图结构诊断与多种真实子图对照，系统分析了双曲归纳偏置在该场景下何时可能有效、何时并不自然成立。

这一表述更符合当前已有证据，也更能避开与“通用双曲 GNN 模型论文”的正面竞争。

---

## 5. 更具创新性的下一步方向

在 [深度调研报告.md](d:/Codes/Math/hyperbolic_lean/docs/深度调研报告.md) 的基础上，结合当前项目现状，我认为最值得投入的创新方向主要有四条。

### 5.1 方向一：把项目推进成 benchmark / protocol 论文

这是当前最稳妥、也最符合已有积累的路线。

目标不是继续增加模型复杂度，而是把以下内容标准化：

- traced formal-math hierarchy 图的数据 schema
- canonical node / edge 定义
- train/valid/test split 协议
- grouped retrieval 评测协议
- diagnostics 指标与报告模板
- 强欧氏 baseline 与双曲对照基线

如果这套东西整理完整，项目就不再只是“一个实验脚本集合”，而会更接近 community-usable benchmark。

### 5.2 方向二：系统区分 explicit 与 synthesized relation

这是我认为最有希望产出真正新结论的方向之一。

调研报告已经指出，Lean/Mathlib 的很多依赖边来自：

- typeclass resolution
- coercion
- elaboration
- 其他 synthesized mechanism

而当前项目也已经观察到，这些边很可能会扭曲“几何半径 ≈ 抽象层级”的直觉。

因此，下一步应考虑显式构建三类图：

1. `explicit-only`
2. `synthesized-only`
3. `mixed`

并在它们上系统比较：

- 结构深度
- relation layer 形态
- hyperbolicity proxy
- grouped retrieval 难度
- GCN/HGCN 表现差异

如果这一步做出来，论文能从“观察到双曲没赢”推进到“解释哪些 Lean-specific 边机制削弱了双曲优势”。

### 5.3 方向三：把训练目标真正对齐到 grouped retrieval

当前项目已经把评测修正成 grouped multi-positive retrieval，但训练目标仍主要是 binary edge classification。这本身就是新的研究空档。

因此，下一步很值得做：

- query-grouped retrieval training
- listwise ranking loss
- contrastive retrieval loss
- grouped query-aware negative sampling

如果在相同图和相同 grouped 协议下，GCN/HGCN 在“训练目标对齐”后结果发生变化，那么这会成为比单纯“再调一个 decoder”更有价值的发现。

### 5.4 方向四：把图表示迁到更真实的 proof-side 下游任务

调研报告强调，纯图拓扑不足以完整表达数学语义。这一点和当前项目的经验高度一致。

因此，更强的新方向不是继续只做 hierarchy edge prediction，而是把当前协议迁到更接近 proving workflow 的任务上，例如：

- premise retrieval 的图正则化
- relation-aware declaration recommendation
- hierarchy navigation / ancestor explanation
- proof exploration 中的可访问前提组织

一旦图表示能真正帮助 LeanDojo 风格的 retrieval 或 proof exploration，项目的价值就会明显上一个层次。

---

## 6. 不推荐继续重投入的方向

为了避免项目后续再次走到边际收益很低的路线上，这里也明确列出几条当前不建议作为主线的方向。

### 6.1 不建议继续把主要资源投在“更强 HGCN 变体”

当前已有实验已经表明，问题并不主要是“decoder 还不够花哨”。

继续在：

- rescaling
- normalization
- 曲率小范围扫描
- 更复杂的局部双曲层

上反复调参，大概率只能得到“稍微稳定一点，但结论不变”的结果。

### 6.2 不建议再把“Lean 图导出成功”当作主要贡献

这部分工程当然重要，但它更应当作为基础设施与 artifact 的一部分，而不是论文的 headline contribution。

### 6.3 不建议只做全图层面的普通 link prediction

原因很简单：

- 图太异质
- 结构解释太弱
- 与 proving 任务距离太远
- 容易被已有网络分析工作或通用 KG baseline 稀释

后续更值得保留的是 relation-aware、hierarchy-focused、task-aligned 的子图和协议。

---

## 7. 可直接写进方案书或论文引言的短版文字

下面这段文字可以直接作为方案书或论文引言的压缩版：

> 尽管 Lean/Mathlib 生态已经具备较成熟的 traced data 与 graph export 工具链，例如 `LeanDojo`、`lean-training-data`、`jixia`、`importGraph`、`lean4export` 与 `mathlib-network`，但现有工作主要聚焦于数据导出、基础网络分析或 theorem proving 中的检索增强，尚未形成一套围绕真实 traced formal-math hierarchy 图的统一任务协议、结构诊断框架与公平模型对照基线。尤其是在双曲表示学习方面，公开文献中尚缺针对 Lean/Mathlib hierarchy 图的系统实验。基于此，本项目的目标不再是简单追求“双曲模型优于欧氏模型”的结论，而是构建一条从 traced repo、normalized trace、precise hierarchy 抽取、coverage-aware relation repair，到 grouped multi-positive retrieval 协议与 relation-aware baseline 对照的完整实验管线，并据此分析在何种图结构、关系定义与任务口径下，双曲归纳偏置才可能对形式化数学图真正有效。当前结果表明，真实 traced Lean hierarchy 图往往表现为浅层、碎片化、叶子占优的 relation forest，而非深层稳定的继承树；因此，双曲模型的失效不应被简单归因于模型能力不足，而应被理解为 formal-math graph 结构与几何归纳偏置之间的条件性错配。该发现进一步提示，后续更具创新性的方向应集中在协议标准化、explicit/synthesized relation 拆分、grouped retrieval 训练目标对齐，以及与 premise retrieval 等真实 proving 工作流的耦合上，而不是继续孤立地追求更复杂的双曲模型变体。

---

## 8. 最终建议

综合来看，当前项目最值得坚持的不是“证明 HGCN 能赢”，而是下面这条更稳、更强、也更有论文价值的主线：

> **把项目做成真实 traced formal-math hierarchy 图的工程基线、协议基线与结构诊断基线，并在此基础上谨慎回答“双曲方法在什么条件下才值得用”。**

如果这条线继续推进顺利，那么即使最终结论仍然是“强欧氏 relation-aware baseline 更稳”，项目也依然具备清晰、可信、可投稿的研究故事。
